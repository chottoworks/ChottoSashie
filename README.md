# ちょっと挿絵

物語の挿絵と、その先の数秒を。ぜんぶ、このPCの中だけで。

物語の挿絵と、その挿絵から作る短い動画を、1つの流れで作るWindowsデスクトップアプリです。
ComfyUIを生成エンジンとして使い、画像も動画もこのPCの中だけで処理します。

## 作る流れ

1. **作品** を登録する
2. **素材作成** で **登場人物**・**背景**・**小物** を作る。3つは画面の中のタブで切り替え、
   順番を決めずに並行して進められる（生成は順番待ちに入り、1件ずつ処理される）
   - 登場人物：顔の候補から基準を選び、そこから **立ち絵**（全身・素背景の1枚）を1枚ずつ作る。
     衣装や小物は立ち絵の **変更** で変える。出来上がりを見て採用すると、その立ち絵が置き換わる。
     元も残したいときは、先に **複製** してから複製した方を変更する
   - 背景・小物：生成するか、手持ちの画像を登録する。背景は、小物を置いたものや時間帯を
     変えたものを **背景のバリエーション** として増やせる
3. **静止画** を作る（背景と立ち絵を1枚へ合成し、姿勢や表情はそのときに指定する）— 挿絵としてはここで完成
4. **シーン・カット** を作る（静止画を起点に動かす）※動画を作る作品だけ
5. **書き出し** で全カットを1本の動画へつなぐ ※動画を作る作品だけ
   （つながずに、カット1本ずつを「シーン・カット」の画面から保存することもできます）

初回セットアップで「挿絵だけ作る／挿絵と動画を作る」を選びます。挿絵だけを選ぶと、
シーン・カットと書き出しの画面は出ず、動画用モデル（数十GB）も取得しません。あとから変えられます。

用語は [用語辞書](docs/terminology.md) に合わせています。

## 動作要件

|  | 最低 | 推奨 |
|---|---|---|
| GPU | NVIDIA製・VRAM 12GB以上 | VRAM 16GB以上 |
| メモリ | 32GB | 48GB以上 |
| 保存先の空き | 80GB以上（挿絵のみ） | 120GB以上（動画も作る場合） |
| ディスク | SSD | NVMe SSD |
| OS | Windows 11 64bit | — |

静止画の合成に使うモデル一式（約30GB）がVRAMへどれだけ載るかで、1枚あたりの待ち時間が
桁違いに変わります。VRAM 12GB未満では生成のたびにモデルの出し入れが起き、1枚に数分以上
かかります。音声付きの動画（MiniMax H3）だけは VRAM 24GB以上かつ Blackwell世代
（RTX 50xx以降）が要ります（任意機能で、満たさない場合は映像のみのWan 2.2を使います）。

要件を満たさない端末でも起動と操作はできます。初回セットアップでその旨をお伝えし、
数十GBのモデルを取得する前に確認します。

## インストールと初回セットアップ

1. インストーラを実行します（管理者権限は要りません。ユーザーごとに入ります）。
2. 初めて起動すると、セットアップが開きます。上から順に進めます。
   - **作品の保存先**: そのままで構いません。別のドライブへ置きたいときだけ変えます。
   - **何を作りますか**: 「挿絵だけ作る」か「挿絵と動画を作る」か。
   - **この端末に合う設定を見る**: GPU・メモリを調べ、勧める生成方法を出します。
   - **ComfyUIの使い方を決める**: 何も入っていない環境なら、既定の
     「完全に専用の環境」のままで構いません。手元のComfyUIやモデルを使う方法も選べます。
   - **ComfyUI環境を用意**: ComfyUI本体の準備 → モデルの取得 → 専用ComfyUIの起動、
     をボタンで進めます。モデルは数十GBあるため、回線によっては時間がかかります。
     起動できると「ノードとモデルの確認」が自動で始まり、揃っていれば
     「セットアップを完了して制作を始める」が押せます。
3. 設定はあとから「設定を確認・変更」で見直せます。

ComfyUI本体とモデルは `%LOCALAPPDATA%\ChottoSashieShared`、作った作品は
`%LOCALAPPDATA%\ChottoSashie` に置きます（どちらも画面から変えられます）。
アンインストールのときに「アプリデータも削除」を選ぶと、作品の保存先からこのアプリが作った
ものと、置き場所の設定を消します（あとから置いた別のファイルには触れません）。ComfyUI本体とモデルの共有フォルダは
別のインストールと共用することがあるため残します。要らなければ手で削除してください。

## 作ったものを取り出す・消す

- **挿絵**: 「静止画」の画面で、合成した1枚の「名前を付けて保存」から保存します。
- **カットの動画**: 「シーン・カット」の画面の「保存」から、1本ずつ保存します。
- **1本の動画**: 「書き出し」で全カットをつなぎ、「名前を付けて保存」で保存します。

アプリの中で作品・人物・背景・小物・静止画・カットを削除すると、そのために作った画像・動画も
一緒に消えます。人物候補は、作り直すと前の回を上書きし（設定で「履歴として残す」にも
できます）、基準画像を決めたあとは選ばなかった候補をまとめて削除できます。
「名前を付けて保存」で取り出したファイルは、アプリの外にあるので消えません。

## 開発環境

- Windows 11 64bit
- Python 3.11〜3.13（配布版に同梱するのは3.13。CIも同じ版で試験します）
- Node.js 22以上
- pnpm 11.9.0
- Rust stable（Tauriのビルド時）
- NVIDIA GPU（生成の実機試験時）

## 起動

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn chotto_sashie_api.main:app --app-dir services/api/src --reload
```

別のターミナルで次を実行します。

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

APIは `http://127.0.0.1:8766`、Web UIは `http://127.0.0.1:1421` です（配布版では、8766番が
埋まっていれば8785番までの空きを順に使い、その番号を画面へ伝えます）。開発データは既定で
`%LOCALAPPDATA%\ChottoSashie\database\app.sqlite3` に保存します。テスト時は環境変数
`CHOTTO_SASHIE_DATA_DIR` で変更できます。

ComfyUI本体とアプリが取得したモデルは、共有フォルダ
`%LOCALAPPDATA%\ChottoSashieShared`（`comfyui`・`models`）へ置きます。置き場所は環境変数
`CHOTTO_SASHIE_SHARED_DIR` で変更できます。

## 置き場所を変える

デスクトップ版は、**作品の保存先**と**ComfyUI・モデルの置き場所**を画面から変えられます。
初回セットアップの最初と、設定ダイアログの「置き場所」にあります。

保存先を変えるときは、今のデータをどうするかを選びます。選べる道は移し先の状態で決まります。

| 移し先の状態 | 選べること |
|---|---|
| 空、またはまだ無い | **今のデータを移す**（DBに残る絶対パスも書き換えます）／**新しく始める**（今のデータは元の場所に残ります） |
| すでに作品がある | **そのまま使う**（どちらのデータも移しません） |
| 関係のないファイルがある | その中に `ChottoSashie` フォルダを作り、そこを保存先にします（混ざると片付けられないため）。そのフォルダも状態に応じて上の2つと同じ扱いです |

別のドライブへ移すときは中身を複製するため、量に応じて時間がかかります。写した量と全体量、
いま写しているファイルを画面に出しますので、終わってひとりでに再起動するまで閉じないでください。

ComfyUI・モデルの置き場所は数十GBあるため、**変えても中身は移しません**。新しい場所に
一式があればそれを使い、無ければ取得し直します。インストールを分けて使い分ける場合も、
ここは同じ場所を指すのがおすすめです。

設定はインストール先の `paths.json` に保存します。インストールごとに別の場所を持てるので、
用途別に分けて使えます。環境変数（`CHOTTO_SASHIE_DATA_DIR` / `CHOTTO_SASHIE_SHARED_DIR`）を
設定している場合はそちらが優先され、画面からは変えられません（開発と試験のため）。

アプリに付いてくる読み取り専用のファイル（`workflows`・`model-manifests`）の場所は、
リポジトリ内で動かしているか、インストールした状態かで変わります。順に
「環境変数 `CHOTTO_SASHIE_RESOURCES_DIR` → パッケージの隣の `_resources` → 親をたどって
両方が揃っている場所」で決めます。どれにも当たらなければ、当てずっぽうの場所を使わずに
止めます。

書き出しで全カットを1本に繋ぐには ffmpeg を使います。これは初回セットアップの
「ComfyUI環境を用意」の「ノードとモデルの確認」に**任意の項目として**含まれます（無くても、カット1本ずつは
保存できます）。手元に無ければそこからアプリが取得し、同じ共有フォルダ（`tools\ffmpeg`）へ
置きます。すでに入っている場合はそちらを使うので取得しません（PATHのほか、winget・scoop・
chocolatey・`C:\ffmpeg`・Program Files も探します）。使うものを明示したいときは環境変数
`CHOTTO_SASHIE_FFMPEG_PATH` に実行ファイルのパスを指定します。挿絵だけを作る設定では
確認の対象から外れます。

## 配布版を作る

デスクトップ版はPythonのAPIを子プロセスとして起動します。開発時はリポジトリの `.venv` を
使いますが、配布先にはリポジトリも仮想環境もありません。そこで、公式のWindows埋め込み可能
パッケージへ依存とアプリ本体を入れた一式を先に組み立て、Tauriの同梱物として配ります。

```powershell
.\.venv\Scripts\python.exe installer\build_api_runtime.py
.\.venv\Scripts\python.exe installer\build_notices.py
.\.venv\Scripts\python.exe installer\build_api_runtime.py
pnpm tauri build
```

アイコンだけを変更した場合も、最後の `pnpm tauri build` で作り直します。
`cargo build --release` だけでは配布用画面の組み込み設定と実行ファイル名の変更が行われず、
`chotto-sashie.exe` が古いまま残るため、配布版の確認には使いません。
確認する実行ファイルは `apps/desktop/src-tauri/target/release/chotto-sashie.exe`、
インストーラは同じ `release` 内の `bundle/nsis/` に出力されます。
実行ファイルを直接起動するときは、隣の `api-runtime` と `app` も必要です。

1つ目で `installer\dist\` に `api-runtime`（Python本体・依存・アプリ本体）と
`app`（ワークフロー・マニフェスト・利用条件の文書）ができます。
2つ目が、その組み立て結果から [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) を作り直します
（実際に入るものだけを見るので、依存を足しても一覧が古くなりません）。3つ目でその一覧を
同梱物へ入れ、4つ目がインストーラを作ります。順番が逆だとTauriが同梱物を見つけられず止まります。

埋め込み版Pythonの版は [`installer/api-runtime.json`](installer/api-runtime.json) で固定し、
取得したものがSHA256と一致しなければ使いません。版を上げるときだけ `--pin` を付けて実行し、
実測値を記録し直します。

## テスト実行

開発時のテストは目的・影響範囲に応じて以下のように使い分けます。

- **日常用（高速スイート）**: 通常の機能改修時
  ```powershell
  .\.venv\Scripts\python.exe -m pytest tests -m "not slow" --durations=20
  ```
- **個別確認（選択実行）**: ランタイム起動・終了の改修時など、変更に関連する低速テストのみを実行
  ```powershell
  .\.venv\Scripts\python.exe -m pytest tests/shared/test_runtime_manager.py -m slow --durations=20
  ```
- **最終確認（全件テスト）**: 手動確認後の最終レビュー前に実行
  ```powershell
  .\.venv\Scripts\python.exe -m pytest tests --durations=20
  ```
