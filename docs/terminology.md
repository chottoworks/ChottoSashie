# 用語辞書

挿絵づくりと動画づくりを1つのアプリに統合した。作品情報の登録から、人物・背景・小物の作成、
それらを組み合わせた静止画の作成までは共通で、動画を作る作品だけが静止画の先へ進む。
利用者に見える文言は、原則としてこの表に合わせる。実装で迷ったらここを更新してから直す。

## 作るものの流れ

| 概念 | 使う言葉 | 使わない言葉 |
|---|---|---|
| 登場人物・背景・小物の総称と、それらを作る画面 | **素材**／画面名は **素材作成** | 素材づくり、準備 |
| 背景と人物の立ち絵を合わせて作った1枚 | **静止画** | キーフレーム、合成画像、シーン |
| 静止画を動かすときの、その1枚から始まるまとまり | **シーン** | ショット群、区間 |
| シーンの中の、連続する1本の動画 | **カット** | ショット、クリップ |
| カットの中の、動きとセリフを割り当てる時間区間 | **ビート** | キーフレーム、タイムラインの駒 |

登場人物・背景・小物は順番に作るものではないので、メニューでは「素材作成」の1つにまとめ、
画面の中のタブで行き来する。タブを切り替えても作業中の内容と生成の進み具合は消えない。
「素材」はこの3つの総称としてだけ使い、立ち絵の衣装替えには使わない（立ち絵の変更）。

静止画1枚が1つのシーンになる。挿絵として使う場合は静止画で完成で、シーン・カット・書き出しの
画面は出さない（初回セットアップで「動画も作る」を選んだ作品だけに出る）。

## 作品と登場人物

| 概念 | 使う言葉 | 使わない言葉 |
|---|---|---|
| 作りたい物語のまとまり | **作品** | プロジェクト、案件 |
| 作品に出てくる人 | **登場人物** | キャラクター、キャラ |
| 人物の見た目・性格の設定 | **プロフィール** | 設定情報、属性 |
| 顔を決めるための比較用画像 | **人物候補** | 候補画像、バリエーション |
| 候補から選んだ1枚 | **基準画像** | ベース画像、リファレンス |
| 基準画像から作る、その人物の全身・素背景の1枚 | **立ち絵** | 全身像、キャラ画像、参照画像 |
| 立ち絵の衣装・小物を変える工程（ボタンは「変更」） | **立ち絵の変更** | 素材づくり、立ち絵のバリエーション、派生 |
| 元の背景から作った、小物を置いた／時間帯を変えた背景 | **背景のバリエーション** | 派生背景、別バージョン |

**小物は合成へ渡さない。** 人物が持つ小物は立ち絵の変更で写し込み、場に置く小物は
背景のバリエーションへ写し込む。**時間帯・天気も背景のバリエーションで変える**——背景1枚だけを
渡す編集でしか変えられず、合成の状況説明に書いても元の背景の時刻が残る。合成に渡せる画像は3枚までで、人物2人と背景で埋まるため。
画面では「人物は2人まで」と出す（3人以上を出したいときは、人物を入れた1枚を背景として
登録し直す）。

**姿勢・表情・向き・立ち位置は合成のときに指定する。** 立ち絵が持つのは顔・髪・体型・衣装で、
そこは合成でも保つ。指定を書かなければ立ち絵のままの姿勢になる。衣装を変えたいときは、
合成で指定するのではなく立ち絵を変更する。

**立ち絵は1回に1枚作る。** 衣装や小物は出来た1枚を「変更」で変えるので、まとめて何枚も
作って当たりを探す必要が無い。変更の結果はすぐには反映せず、その立ち絵の隣に出して見せる。
見比べて**「採用する」**（その立ち絵を置き換える。元の画像は残らない）か、**「再生成する」**
（同じ指示で作り直す）かを選ぶ。要らない結果は「やめる」で捨てる。変更は常に置き換えなので、
衣装違いを並べて持ちたいときは、先に**「複製」**で同じ立ち絵を1枚増やしてから、複製した方を
変更する（変えてから残し方を選ばせると、何が起きるのかを2か所で考えることになる）。

**背景のバリエーションの名前は「元の名前（違い）」**（「教室（夕方）」）。静止画で背景を選ぶ一覧には
名前しか出ないので、同じ場所の背景は名前で見分ける。違いを別の札として出すことはしない（名前と
同じことを二重に出すだけで、名前を変えると食い違う）。元の背景の名前を変えると、この形のままの
バリエーションの名前も付け直す。背景の一覧には元の背景だけを並べ、バリエーションは枚数だけ出して、
押すとグループの画面で元とバリエーションをまとめて扱う。

**立ち絵は人物の実体**で、静止画は背景と立ち絵を合成して作る。衣装や小物を変えた立ち絵を
複数持てるので、静止画を作るときにどれを使うかを選ぶ。合成のたびに選ばせないよう、選んで
いないときに使う1枚を**既定の立ち絵**と呼ぶ。立ち絵の一覧で既定にするボタンは、短く
**「既定」**とする（押してある1枚が既定）。誰も既定を選んでいないうちは、一覧の先頭の1枚が
既定になる（見えている並びと既定が食い違わないように）。並びは「←」「→」で入れ替える。

**「参照画像」は画面に出さない。** 生成エンジンへ渡す画像の総称としては使うが、利用者から
見れば「立ち絵」と「背景」であって、参照画像という枠は内部の都合である。

作る流れの中では上の呼び方で通す。これは言葉を避けるためではなく、同じものを画面ごとに
別の名前で呼ばないため。仕組みの話をする場面（おすすめ設定の理由、セットアップ）では
「LoRA」「ステップ」のようにそのままの名前で書いてよい（次の線引きに従う）。

## 画面に出す言葉の線引き

このアプリを使うのは、ComfyUIで画像を作っている人である。その世界で普通に使われている
言葉は、**言い換えずにそのまま出す**。ComfyUI、LoRA、プロンプト、ノード、VRAM、ステップ、
seed などは、噛み砕くとかえって何を指しているのか分からなくなる。

数値や形式の名前（fp8、fp8mixed、nvfp4、4ステップ、14B など）も出してよいが、**初めて出る
ところで短く補う**（「fp8＝重みを8ビットに落とした版」）。名前を消すのではなく、意味を添える。

出さないのは次の2つ。

- **プログラマーにしか馴染みのない表現** — 変数名やAPIの識別子（`base_url`、`image_json`）、
  例外名、HTTPの状態番号、内部のファイル名（`01_face_closeup.png`）。利用者が読んでも
  何もできない。
- **このアプリ固有の内部処理に由来する表現** — 作りの都合から出た呼び名（「参照画像」
  「状態画像」）や、指示文の組み立て・英語への変換といった処理の説明。利用者から見れば
  「立ち絵を背景に合成した」だけである。

## 待ち時間の書き方

どれだけ待てるかは利用者が決めることなので、**こちらで断定しない**。「待てる速さがある」
「時間に耐えられる構成」「現実的な時間で終わる」「実用にならない」のような書き方はしない。

書くのは実際の動作だけにする。何をするか（選択肢を多く取る、立ち絵を多めに作る、
高速化LoRAを外してステップ数を増やす）と、それによって時間がどう変わるか
（1枚あたりの時間が長くなる、待ち時間を短くできる）を並べ、選ぶのは利用者に任せる。

## カットの指示

動きの指示・セリフ・環境音は別々の欄にする。MiniMax H3 は1本のテキストで映像と音声の
両方を条件付けるため、混ぜて渡すと動きの説明文がそのまま読み上げられてしまう。

| 概念 | 使う言葉 | 使わない言葉 |
|---|---|---|
| カットの中で何が動くか（人物の動きとカメラの動き） | **動き・カメラワークの指示** | プロンプト、モーション |
| 登場人物が話す言葉・語り | **セリフ・ナレーション** | 音声プロンプト、ボイス |
| そのセリフを誰が言うか | **話す人** | 話者、スピーカー、キャラ |
| 画面の外の声（話す人を持たない行） | **ナレーション** | ボイスオーバー、VO |
| 声以外の、その場で鳴っている音 | **環境音・効果音** | SE、アンビエント |
| 画面の外で鳴る音楽 | **音楽** | BGM、劇伴、サントラ |
| 前のカットの続きではない見え方の1枚から始める | **起点の構図** | 再構図、リフレーミング |
| カットの始まりに使う1枚 | **起点** | 開始フレーム、initイメージ |
| カットの終わりに固定する1枚 | **着地の絵** | 終端フレーム、ラストフレーム |
| カットに書いておく自分用の覚え書き | **コメント** | メモ、ノート、注記 |
| 全カットを1本の動画にする | **書き出し** | エクスポート、結合、コンカット |
| カット1本を手元のファイルにする | **保存** | ダウンロード、個別エクスポート、単体出力 |
| つないだ動画を手元のファイルにする | **名前を付けて保存** | ダウンロード |

カットの中のカメラの動き（寄る・引く・人物を追う）は、人物の動きと同じ欄に書く。MiniMax H3 の
公式の例も、カメラの動きを動作の記述の中に続けて書いている。起点の構図は、カットの最初の
1枚を作り直すための指示で、書いただけでは使われない（「起点を作り直す」「着地の絵にする」を
押したときだけ使う）。名前に「カメラ」を入れると、カットの中のカメラの動きを書く欄に読める。

セリフは**行で書き、行ごとに話す人を選ぶ**（「セリフを足す」で1行増やす）。上から順に
読み上げられる。話す人はその静止画にいる人物とナレーションから選ぶ。1つの欄に二人分を
書く形にしないのは、話す人を決めないと、二人いる場面でどちらが口を動かすかがモデル任せに
なるため。話す人を見分ける手がかり（配置・性別・年齢帯・髪）が無いときは、その旨と
「配置を書くと名指しできる」ことを行の下に出す。

セリフ欄と環境音欄は、音を作れるモデル（MiniMax H3）を選んだときだけ出す。Wan 2.2 は
音を作らないので、出すと「書いたのに反映されない」欄になる。

**セリフ以外の指示は、生成のときに自動で英語へ直す。** 動きの指示とセリフの両方が
日本語だと、MiniMax H3 は両者を区別できず、説明文まで読み上げる（実機で確認）。利用者は
日本語のまま書いてよく、変換はアプリが行う。セリフは訳さない——読み上げてほしい言葉
そのものなので、日本語のまま引用符の中へ入れる。**この変換は画面で説明しない**——
利用者から見れば内部の処理で、結果は「生成に使う文」を読めば分かる。

| 概念 | 画面の呼び方 | この画面では使わない言い方 |
|---|---|---|
| 生成エンジンへ実際に送る文 | **生成に使う文** | 送信内容、組み立て結果 |
| その文だけを先に作る | **生成に使う文を作る** | 下見、プレビュー |
| その文を自分で書き換える | **この文を直接書き直す** | オーバーライド |

ここで「プロンプト」と呼ばないのは、その語を避けるためではない。この画面には
「動きの指示」「セリフ」「環境音」という書く欄が別々にあり、どれもプロンプトの材料になる。
出来上がった1本を「プロンプト」と呼ぶと、どの欄のことか分からなくなる。**欄が1つしかない
画面（背景・小物の生成など）では「生成プロンプト」と呼んでよい。**

「生成に使う文」は**用意できたものだけを出す**。まだ作っていない文、指示を変えたあとの
古い文は画面に出さず、作り直しを促す。中途半端な文を見せると、直したつもりの内容と
実際の結果が食い違う。

**つなぐのに必要なものは、アプリが用意する。名前は隠さない。** 外部の配布物（ffmpeg）を
入れることになるので、「ffmpeg（動画をつなぐ処理エンジン）」と名前を出し、取得元・利用条件・
取得する量を押す前に添える。何が入るのか分からないまま進ませない。内部の処理を説明しない
という方針（下記）と矛盾しない——これは「何を入れるか」の開示で、処理の説明ではない。

**つなぐ機能は任意。** 無くても、カット1本ずつは「シーン・カット」の画面から保存できるので、
セットアップの完了は止めない。書き出し画面でも「つながなくても、カット1本ずつなら
『シーン・カット』の画面から保存できます」と出し、行き止まりにしない。

**保存するファイル名は、作品名とシーン名から作る。** `カット01.mp4` では、後から見て
どの作品のどの場面か分からない。`作品名_シーン名_カット01.mp4` の形にする。保存先と名前は
OSの「名前を付けて保存」ダイアログで変えられる。保存し終えたら、その名前を添えて画面で
知らせる（保存は画面が変わらないので、黙って終わると気づけない）。取り消したときは
失敗ではないので、何も出さない。

**カットの操作は置き場所で意味を分ける。** 「保存」と「削除」はそのカット自体をどうするかなので
見出しの行に置き、「動画を生成／作り直す」は設定を確かめてから押すものなので折りたたみの
一番下に置く。畳んだカットを勢いで作り直してしまわないようにするため。

**書き出しに必要なものは、アプリが用意する。** 「ffmpegを導入してPATHを通すか、
環境変数を設定してアプリを再起動してください」のような案内は開発者向けの
指示で、利用者には何のことか分からない。用意する場所は初期設定の「ComfyUI環境を用意」の**「ノードとモデルの確認」**で、
モデルやノードの不足と同じ並びに「足りないもの」として出し、「用意する」を押せば済む形に
する。取得する量は押す前に添え、1回で済むことも書く。書き出し画面には専用のボタンを置かず、
「ノードとモデルの確認」から用意できると行き先だけを示す（足りないものを2か所で操作させない）。

**コメントは生成に一切渡さない。** 「あとで撮り直す」のような覚え書きを生成へ渡すと、
書いた覚えのない指示として効く。生成に使う文にも入らないので、書き換えても文は作り直さず、
文を直接書き直している間も書ける。カットの一覧では、設定を畳んだままでも読める位置に出す。

## ビートの作り方

| 値 | 表示 | 補足 |
|---|---|---|
| `single` | **まとめて1回で作る** | 速い。時間の割り振りはモデル任せ |
| `split` | **ビートごとに分けて作る** | 時間どおり。ビートの数だけ時間がかかる |

## 生成のパラメータ

| 項目 | 範囲・既定 | 説明文 |
|---|---|---|
| 候補の**変化強度** | 2.0〜3.5（0.1刻み）、既定3.0 | 低いと画風に忠実で穏やか、高いと顔立ちと候補ごとの差が強く出ます。 |
| 候補の**枚数** | 8 / 10 / 12、既定8 | — |

同じ意味のつまみは、どの画面でも同じ範囲・同じ既定・同じ説明文にする。

ここに挙げたつまみと「合成の丁寧さ」「動画の作り方」は、**選び直した値がそのまま次回の既定**になる（この端末の設定として覚える）。
表の「既定」は、まだ一度も選んでいないときの値を指す。

書き出しのfpsは覚えない。既定は「カットに合わせる（24 fps）」で、カット動画が実際に持つ
fpsを読んで使う。前回の値を覚えると、作り方を変えた作品にも前の作品の値が残り、コマが
間引かれたり水増しされたりする（16を覚えたままMiniMax H3のカットを書き出していた）。

## この端末に合う設定（おすすめ）

| 概念 | 使う言葉 |
|---|---|
| GPU・メモリを調べる | **この端末に合う設定を見る** |
| 調べた結果の段 | **余裕あり / 標準 / 控えめ / 最小**（判定できないときは「判定できません」） |
| 提案を既定にする | **おすすめ設定を使う**（押すまで何も変わらない） |
| 適用済みの状態 | **適用済み** |

おすすめは必ず**値と理由を並べて**出す。条件を満たさず下げたときは、その理由も添える
（黙って別のものを勧めない）。構成を確認できないときは何も勧めず、手動で選んでもらう。

## セットアップ

| 値 | 表示 |
|---|---|
| `existing_comfyui` | **既存のComfyUIをそのまま使う** |
| `managed_external_models` | **専用ComfyUIを起動し、既存モデルを参照する** |
| `managed_dedicated` | **完全に専用の環境（モデルもアプリ管理）** |

「生成エンジン」＝ComfyUIのこと。**ComfyUIという名前は隠さない。** 接続先や導入の話のように、
相手がComfyUIそのものだと分かっているところでは「ComfyUI」と書く。設定によって専用と既存の
どちらにもなりうる場面（起動状態の表示など）では、その両方を指せる「生成エンジン」を使う。

## 状態と操作

| 概念 | 使う言葉 |
|---|---|
| 実行中の処理を止める | **中止する** |
| 消えたものを確認してから消す | **削除する**（確認ダイアログで内訳を提示） |
| 同じものを作り直す | **作り直す**（前の回は残す） |
| 生成の回 | **表示する回** |
| 接続できている | **生成準備完了** |
| 接続できていない | **生成エンジンに接続できません** |
